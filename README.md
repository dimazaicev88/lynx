# Lynx

**Lynx** — экспериментальный строго типизированный язык, компилируемый в
JavaScript. Компилятор `lynxc` написан на Go: он разбирает исходный код,
проверяет типы и только затем генерирует JavaScript.

> Проект находится в разработке. Синтаксис и поведение языка могут меняться.

## Быстрый старт

Для сборки требуется **Go 1.22 или новее**.

```bash
make build
```

То же самое можно сделать без Make:

```bash
go build -o bin/lynxc ./cmd/lynxc
```

Проверьте и скомпилируйте готовый пример:

```bash
./bin/lynxc -check examples/functions.lynx
./bin/lynxc examples/functions.lynx
```

По умолчанию JavaScript выводится в стандартный поток вывода. Чтобы сохранить
результат в файл, используйте `-o`:

```bash
./bin/lynxc -o functions.js examples/functions.lynx
```

Небольшая программа на Lynx:

```lynx
fun makeGreeting(name: String = "Lynx"): String {
  return "Hello, " + name + "!"
}

val greeting = makeGreeting()
val customGreeting = makeGreeting(name = "world")
```

Сгенерированный JavaScript:

```js
function makeGreeting(name = "Lynx") {
    return "Hello, " + name + "!";
}

const greeting = makeGreeting();
const customGreeting = makeGreeting("world");
```

Аннотации типов нужны только компилятору и не попадают в результат.

## Возможности и ограничения

Сейчас язык поддерживает:

- типы `Number`, `String`, `Array`, `Any`, `Unknown`, `Null` и nullable-типы
  `T?`;
- неизменяемые значения `val` и изменяемые переменные `var`;
- вывод типов по начальному значению;
- именованные функции, значения параметров по умолчанию и вариадические
  параметры;
- позиционные и именованные аргументы;
- лямбды, функциональные типы и замыкания;
- арифметические выражения, строковую конкатенацию, массивы, индексацию и
  свойство `.length`;
- вложенные области видимости и диагностику с указанием позиции в исходнике.

Условия, циклы, логические операторы, объекты, классы, импорты и стандартная
библиотека пока не реализованы. Проверки на `null` и автоматическое сужение
nullable-типов также отсутствуют.

## Командная строка

```text
lynxc [опции] <файл.lynx>
```

| Опция       | Назначение                                             |
|-------------|--------------------------------------------------------|
| `-o <файл>` | записать JavaScript в файл вместо stdout               |
| `-check`    | только проверить программу, не генерировать JavaScript |
| `-version`  | вывести версию компилятора                             |

Опции можно располагать до или после имени исходного файла:

```bash
./bin/lynxc examples/basic.lynx -o basic.js
```

Для чтения программы из stdin передайте `-` вместо имени файла:

```bash
./bin/lynxc - < examples/functions.lynx
```

Коды завершения: `0` — успех, `1` — ошибка ввода-вывода или компиляции,
`2` — неверные аргументы командной строки.

## Основы синтаксиса

Точки с запятой необязательны:

```lynx
val first = 1
val second = 2;
val third = first + second
```

Перевод строки не завершает инструкцию. Поэтому пустой `return` перед другим
выражением следует записывать с `;`, иначе следующее выражение станет
возвращаемым значением:

```lynx
fun noop() {
  return;
  noop()
}
```

Поддерживаются однострочные и блочные комментарии:

```lynx
// Однострочный комментарий

/* Блочный
   комментарий */
```

Блок `{ ... }` создаёт вложенную область видимости. Сам по себе блок не задаёт
условие или цикл.

## Переменные и области видимости

Неизменяемая переменная объявляется через `val` и обязана иметь
начальное значение:

```lynx
val answer = 42
val language: String = "Lynx"
```

Изменяемая переменная объявляется через `var`:

```lynx
var count = 0
count = count + 1

var total: Number = 10
total = 20
```

Общие формы объявления:

```text
val имя = выражение
val имя: Тип = выражение
var имя = выражение
var имя: Тип = выражение
var имя: Тип
```

Для `var` без начального значения аннотация типа обязательна:

```lynx
var pending: Number
pending = 5
```

Сейчас компилятор не отслеживает, была ли такая переменная инициализирована
перед чтением. В сгенерированном JavaScript она объявляется через `let` без
начального значения, поэтому присваивание перед использованием остаётся
ответственностью программиста.

Правила объявлений и присваиваний:

- если аннотация отсутствует, тип выводится из начального значения;
- тип `var` фиксируется при объявлении;
- повторное присваивание `val` запрещено;
- повторное объявление имени в одной области видимости запрещено;
- внутренний блок может обращаться к именам внешней области;
- имя переменной не должно конфликтовать с именем функции.

При генерации `val` преобразуется в JavaScript `const`, а `var` — в `let`.

## Типы

| Тип             | Описание                                                       |
|-----------------|----------------------------------------------------------------|
| `Number`        | число; `Int` является синонимом `Number`                       |
| `String`        | строка                                                         |
| `Array`         | массив; в аннотации эквивалентен `Array<Any>`                  |
| `Any`           | динамическое значение; статические проверки для него ослаблены |
| `Unknown`       | значение неизвестного типа                                     |
| `Null`          | тип литерала `null`                                            |
| `T?`            | значение типа `T` или `null`                                   |
| `(T1, T2) -> R` | функция с типами параметров `T1`, `T2` и результатом `R`       |

Примеры аннотаций:

```lynx
val count: Number = 10
var name: String = "Lynx"
val items: Array = [1, 2, 3]
val missing: Null = null
var nickname: String? = null
```

### Совместимость типов

- `Number`, `String` и `Array` несовместимы друг с другом.
- Значение типа `Any` можно присвоить переменной любого типа; в `Any` также
  можно присвоить значение любого типа.
- `Unknown` можно присвоить только в `Unknown` или `Any`.
- `null` можно присвоить только в `Null`, nullable-тип, `Any` или `Unknown`.
- Nullable-значение нельзя присвоить в соответствующий non-nullable-тип.

`T?` описывает допустимое значение, а не необязательность аргумента. Например,
параметр `name: String?` всё равно обязателен при вызове, если у него нет
значения по умолчанию.

К `Unknown` и nullable-значениям нельзя применять арифметические операторы,
индексацию и `.length`. Конструкций для проверки и сужения таких типов пока
нет.

### Массивы

Массивы создаются литералами:

```lynx
val numbers = [1, 2, 3]
val first: Number = numbers[0]
val size: Number = numbers.length
val empty = []
```

Компилятор сохраняет тип элементов для проверки индексации:

- `[1, 2, 3]` имеет внутренний тип `Array<Number>`;
- `[1, "two"]` — `Array<Any>`;
- `[1, null]` — `Array<Number?>`;
- `[]` — `Array<Any>`.

Запись `Array<T>` используется в диагностике и описании внутренних типов. В
исходном коде параметризованная аннотация пока недоступна: используйте `Array`.

Индекс должен иметь тип `Number` или `Any`. Вложенные массивы можно индексировать
последовательно: `matrix[0][1]`.

## Выражения

Поддерживаются следующие операции, в порядке убывания приоритета:

1. вызов `f(x)`, индексация `a[i]`, доступ к свойству `a.length`;
2. унарные `+` и `-`;
3. умножение `*`, деление `/`, остаток `%`;
4. сложение `+` и вычитание `-`.

Скобки изменяют порядок вычисления:

```lynx
val result = -(1 + 2) * 3
```

Операторы `-`, `*`, `/`, `%` работают с числами. Оператор `+` складывает числа
или выполняет строковую конкатенацию; строку можно объединять со строкой или
числом:

```lynx
val message = "Result: " + 42
```

Индексация и `.length` доступны как для массивов, так и для строк:

```lynx
val word = "Lynx"
val firstCharacter = word[0]
val length = word.length
```

Операторы сравнения и логические операторы пока не поддерживаются.

## Управляющие конструкции

> `if` и `switch` описаны как планируемые возможности. Их поведение должно
> соответствовать Go, но текущая версия компилятора их ещё не поддерживает.

### Условный оператор `if`

`if` выполняет блок, если условие истинно. Необязательный `else` задаёт
альтернативную ветвь, а цепочка `else if` позволяет проверить несколько условий:

```lynx
if value > 0 {
  return "positive"
} else if value < 0 {
  return "negative"
} else {
  return "zero"
}
```

Правила соответствуют Go:

- условие должно иметь тип `Boolean`; числа, строки и `null` не преобразуются
  неявно в булево значение;
- скобки вокруг условия не требуются;
- фигурные скобки обязательны, даже если ветвь содержит одну инструкцию;
- выполняется только первая ветвь с истинным условием; если ни одно условие не
  истинно, выполняется `else`, при его отсутствии выполнение продолжается после
  всей конструкции;
- каждая ветвь создаёт собственную область видимости.

### Оператор `switch`

`switch` сравнивает значение выражения со значениями в `case` и выполняет первый
подходящий вариант:

```lynx
switch value {
case 0:
  return "zero"
case 1, 2:
  return "one or two"
default:
  return "other"
}
```

Семантика соответствует Go:

- выражение после `switch` вычисляется один раз;
- один `case` может содержать несколько значений через запятую;
- выполняется только первый подходящий `case`; автоматического проваливания в
  следующий вариант нет, поэтому завершать каждый `case` через `break` не нужно;
- необязательный `default` выполняется, если не подошёл ни один `case`;
- `break` можно использовать для досрочного выхода из `switch`;
- `fallthrough` передаёт управление в следующий `case` без проверки его условия;
- каждый `case` и `default` имеет собственную неявную область видимости.

Как и в Go, выражение после `switch` можно опустить. Тогда варианты проверяются
как булевы условия по порядку, что эквивалентно `switch true`:

```lynx
switch {
case value < 0:
  return "negative"
case value > 0:
  return "positive"
default:
  return "zero"
}
```

## Функции

Общий синтаксис объявления:

```text
fun имя(параметр: Тип, параметр: Тип = значение): ТипВозврата {
  ...
  return выражение
}
```

Все параметры должны иметь аннотацию типа. Тип возврата можно опустить — тогда
функция считается `void` и не возвращает значения.

```lynx
fun add(a: Number, b: Number = 1): Number {
  return a + b
}

fun log(value: Number) {
  return
}

val two = add(1)
val five = add(a = 2, b = 3)
```

### Параметры и аргументы

Значение по умолчанию задаётся через `=` и проверяется на совместимость с типом
параметра. Оно может ссылаться на ранее объявленные параметры:

```lynx
fun wrap(prefix: String, value: String = prefix): String {
  return value
}
```

Вызов поддерживает позиционные и именованные аргументы:

```lynx
add(1, 2)
add(1)
add(b = 5, a = 2)
```

Правила вызова:

- позиционный аргумент не может идти после именованного;
- один параметр нельзя передать дважды;
- все обязательные параметры должны получить аргумент;
- именованные аргументы переставляются в позиционные при генерации JavaScript;
- если между переданными аргументами пропущен параметр со значением по
  умолчанию, компилятор подставляет `undefined`.

Например:

```lynx
fun f(a: Number = 1, b: Number = 2): Number {
  return b
}

val result = f(b = 5) // JavaScript: f(1, 5)
```

Вариадический параметр записывается через `...` после типа:

```lynx
fun first(numbers: Number...): Number {
  return numbers[0]
}

val value = first(1, 2, 3, 4)
```

Он должен быть последним и единственным вариадическим параметром функции, не
может иметь значения по умолчанию и не может быть передан по имени. Внутри
функции `numbers` ведёт себя как массив чисел; в JavaScript используется
rest-параметр `...numbers`.

### Возврат значения

- `return выражение` возвращает значение, совместимое с объявленным типом.
- Пустой `return` допустим только в функции без аннотации возврата.
- В функции без аннотации возврата `return выражение` запрещён.
- Если тип возврата указан, в теле должен быть хотя бы один `return` со
  значением.

Проверка наличия `return` не является анализом всех путей выполнения: при
появлении условий компилятору потребуется более строгий анализ.

Сигнатуры функций собираются до проверки тел, поэтому доступны рекурсия, вызов
функций, объявленных ниже, и взаимные вызовы. Именованные функции можно
объявлять только на верхнем уровне программы.

## Лямбды и функциональные типы

Лямбда записывается в фигурных скобках: типизированные параметры, `->` и одно
выражение, результат которого возвращается:

```lynx
val sum = { x: Number, y: Number ->
  x + y
}

val total = sum(1, 5)
```

Результат транспиляции:

```js
const sum = (x, y) => x + y;
const total = sum(1, 5);
```

Тип лямбды выводится автоматически. Его также можно указать явно:

```lynx
val sum: (Number, Number) -> Number = {
  x: Number, y: Number -> x + y
}
```

Функциональные типы допустимы в параметрах и возвращаемых значениях:

```lynx
fun apply(f: (Number) -> Number, value: Number): Number {
  return f(value)
}

val incremented = apply({ n: Number -> n + 1 }, 10)
```

Лямбда без параметров записывается как `{ -> 42 }`. Лямбды поддерживают
замыкания:

```lynx
val outer = { x: Number -> { y: Number -> x + y } }
val addOne = outer(1)
val result = addOne(41) // 42
```

Текущие ограничения:

- тело лямбды состоит из одного выражения; блок и `return` недоступны;
- все параметры должны иметь типы;
- значения по умолчанию и вариадические параметры не поддерживаются;
- тело должно производить значение, поэтому результат `void`-функции вернуть
  нельзя;
- именованные аргументы при вызове функции-значения не поддерживаются;
- вызывать можно только имя функции или переменной: вызов произвольного
  выражения, например `functions[0](1)`, пока недоступен.

## ООП

> `class` и `interface` описаны как планируемые возможности. Их поведение должно
> соответствовать Kotlin, но текущая версия компилятора их ещё не поддерживает.

### Классы

Класс объявляется через `class`. Конструктор записывается в заголовке
класса; его параметры, помеченные `val` или `var`, становятся свойствами:

```lynx
class User(val name: String, var age: Number = 0) {
  fun greet(): String {
    return "Hello, " + name + "!"
  }
}

val user = User("Lynx", 3)
val renamed = User(name = "world")
```

Результат транспиляции:

```js
class User {
    constructor(name, age = 0) {
        this.name = name;
        this.age = age;
    }

    greet() {
        return "Hello, " + this.name + "!";
    }
}

const user = new User("Lynx", 3);
```

Свойство объявляется через `val` (только чтение) или `var` (изменяемое). Его
можно описать и в теле класса:

```lynx
class Counter(val start: Number = 0) {
  var count: Number = start

  fun increment(): Number {
    count = count + 1
    return count
  }
}

val counter = Counter()
val next = counter.increment()
```

Объект создаётся вызовом `ИмяКласса(аргументы)`, без `new`. Значения по
умолчанию, позиционные и именованные аргументы работают так же, как у функций.
Доступ к членам — через точку:

```lynx
val user = User("Lynx")
val greeting = user.greet()
user.age = 4
```

#### Наследование

Родительский класс указывается после двоеточия вместе с аргументами
своего конструктора:

```lynx
class Animal(val name: String) {
  fun speak(): String {
    return "..."
  }
}

class Dog(val name: String): Animal(name) {
  override fun speak(): String {
    return "Woof"
  }
}

class QuietDog(val name: String): Dog(name) {
  override fun speak(): String {
    return "[" + super.speak() + "]"
  }
}
```

Переопределение
помечается `override`; реализация родителя доступна через `super`.

#### Абстрактные классы

Абстрактный класс объявляется через `abstract class` и не может быть создан
напрямую. Абстрактный метод не имеет тела и обязан быть переопределён:

```lynx
abstract class Shape {
  abstract fun area(): Number

  fun describe(): String {
    return "area = " + area()
  }
}

class Square(val side: Number): Shape {
  override fun area(): Number {
    return side * side
  }
}
```

Правила:

- классы объявляются на верхнем уровне программы, как именованные функции;
- класс наследует не более одного класса; интерфейсы перечисляются после
  родителя через запятую;
- члены класса публичны; модификаторы доступа (`private`, `protected`,
  `public`) появятся позже;

### Интерфейсы

Интерфейс задаёт контракт без состояния. Метод без тела — абстрактный; метод с
телом даёт реализацию по умолчанию. Свойства объявляются без начального
значения:

```lynx
interface Named {
  val name: String

  fun describe(): String {
    return "named " + name
  }
}

interface Serializable {
  fun serialize(): String
}

class User(val name: String, val age: Number): Named, Serializable {
  override fun serialize(): String {
    return name + " (" + age + ")"
  }
}

val user = User("Lynx", 3)
val description = user.describe() // "named Lynx" — реализация по умолчанию
```

Правила:

- методы с телом можно не переопределять; методы без тела класс обязан
  реализовать, переопределение помечается `override`;
- свойства интерфейса не хранят значения — их предоставляет класс;
- если два интерфейса дают реализацию одного и того же метода, класс должен
  переопределить его сам;
- интерфейсы существуют только во время компиляции: в JavaScript они не
  попадают, а реализация по умолчанию подставляется в классы, которые её не
  переопределили.

## Диагностика ошибок

Компилятор сообщает имя файла, строку, столбец и показывает фрагмент исходника:

```text
$ ./bin/lynxc bad.lynx
bad.lynx:1:17: error: cannot assign a value of type String to variable "a" of type Number
val a: Number = "x";
                ^
```

Одна компиляция может вывести несколько независимых ошибок проверки типов.
JavaScript не генерируется, если программа содержит ошибки.

## Примеры и разработка

В каталоге `examples/` находятся программы, которые можно использовать как
дополнительные примеры:

| Файл                      | Содержимое                                   |
|---------------------------|----------------------------------------------|
| `examples/basic.lynx`     | переменные, типы и строковая конкатенация    |
| `examples/arrays.lynx`    | массивы, вложенная индексация и `.length`    |
| `examples/functions.lynx` | функции, аргументы и вариадические параметры |
| `examples/lambdas.lynx`   | лямбды, функциональные типы и замыкания      |

Перед отправкой изменений в компилятор выполните:

```bash
make fmt
make test
make vet
```

Основные этапы компиляции разделены по пакетам: `internal/lexer`,
`internal/parser`, `internal/checker` и `internal/codegen`. Пакет
`internal/compiler` объединяет их, а `cmd/lynxc` реализует интерфейс командной
строки.
