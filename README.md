# Lynx

**Lynx** — экспериментальный строго типизированный язык, компилируемый в
JavaScript. Компилятор `lynxc` написан на Go: он разбирает исходный код,
проверяет типы и только затем генерирует JavaScript.

> Проект находится в разработке. Синтаксис и поведение языка могут меняться.

## Быстрый старт

Для сборки требуется **Go 1.22 или новее**.

```bash
make build
```

То же самое можно сделать без Make:

```bash
go build -o bin/lynxc ./cmd/lynxc
```

Проверьте и скомпилируйте готовый пример:

```bash
./bin/lynxc -check examples/functions.lynx
./bin/lynxc examples/functions.lynx
```

По умолчанию JavaScript выводится в стандартный поток вывода. Чтобы сохранить
результат в файл, используйте `-o`:

```bash
./bin/lynxc -o functions.js examples/functions.lynx
```

Небольшая программа на Lynx:

```lynx
fun makeGreeting(name: String = "Lynx"): String {
  return "Hello, " + name + "!"
}

val greeting = makeGreeting()
val customGreeting = makeGreeting(name = "world")
```

Сгенерированный JavaScript:

```js
function makeGreeting(name = "Lynx") {
    return "Hello, " + name + "!";
}

const greeting = makeGreeting();
const customGreeting = makeGreeting("world");
```

Аннотации типов нужны только компилятору и не попадают в результат.

## Возможности и ограничения

Сейчас язык поддерживает:

- типы `Number`, `String`, `Boolean`, `Array<T>`, `Any`, `Unknown`, `Null` и
  nullable-типы `T?`;
- не переприсваиваемые переменные `val` и изменяемые переменные `var`;
- вывод типов по начальному значению и проверку инициализации;
- сужение nullable-типов и `Unknown` по условиям;
- условия `if`, циклы `for`, `switch`, `break`, `continue` и `fallthrough`;
- именованные функции, значения параметров по умолчанию и вариадические
  параметры;
- позиционные и именованные аргументы;
- лямбды, функциональные типы и замыкания;
- арифметику, сравнения, логические операторы, массивы и безопасную индексацию;
- встроенные функции `println` и `toString`;
- вложенные области видимости и диагностику с указанием позиции в исходнике.

Объекты, классы, импорты, enum, `match`, `throws`, `raise` и `try`/`catch`
пока не реализованы. Соответствующие разделы ниже описывают планируемые
возможности.

## Командная строка

```text
lynxc [опции] <файл.lynx>
```

| Опция       | Назначение                                             |
|-------------|--------------------------------------------------------|
| `-o <файл>` | записать JavaScript в файл вместо stdout               |
| `-check`    | только проверить программу, не генерировать JavaScript |
| `-version`  | вывести версию компилятора                             |

Опции можно располагать до или после имени исходного файла:

```bash
./bin/lynxc examples/basic.lynx -o basic.js
```

Для чтения программы из stdin передайте `-` вместо имени файла:

```bash
./bin/lynxc - < examples/functions.lynx
```

Коды завершения: `0` — успех, `1` — ошибка ввода-вывода или компиляции,
`2` — неверные аргументы командной строки.

## Основы синтаксиса

Точки с запятой необязательны:

```lynx
val first = 1
val second = 2;
val third = first + second
```

Перевод строки не завершает инструкцию. Поэтому пустой `return` перед другим
выражением следует записывать с `;`, иначе следующее выражение станет
возвращаемым значением:

```lynx
fun noop() {
  return;
  noop()
}
```

Поддерживаются однострочные и блочные комментарии:

```lynx
// Однострочный комментарий

/* Блочный
   комментарий */
```

Блок `{ ... }` создаёт вложенную область видимости. Сам по себе блок не задаёт
условие или цикл.

## Переменные и области видимости

Переменная без возможности повторного присваивания объявляется через `val` и
обязана иметь начальное значение. `val` не делает неизменяемым само значение или
его внутреннее состояние:

```lynx
val answer = 42
val language: String = "Lynx"
```

Изменяемая переменная объявляется через `var`:

```lynx
var count = 0
count = count + 1

var total: Number = 10
total = 20
```

Общие формы объявления:

```text
val имя = выражение
val имя: Тип = выражение
var имя = выражение
var имя: Тип = выражение
var имя: Тип
```

Для `var` без начального значения аннотация типа обязательна:

```lynx
var pending: Number
pending = 5
```

Читать переменную до присваивания нельзя. Компилятор анализирует ветвления:
после `if` переменная считается инициализированной только если значение было
присвоено на каждом возможном пути. Присваивание внутри цикла не гарантирует
инициализацию после него, поскольку тело может не выполниться ни разу.

Правила объявлений и присваиваний:

- если аннотация отсутствует, тип выводится из начального значения;
- тип `var` фиксируется при объявлении;
- повторное присваивание `val` запрещено;
- повторное объявление имени в одной области видимости запрещено;
- внутренний блок может обращаться к именам внешней области;
- имя переменной не должно конфликтовать с именем функции.

При генерации `val` преобразуется в JavaScript `const`, а `var` — в `let`.

## Типы

| Тип             | Описание                                                           |
|-----------------|--------------------------------------------------------------------|
| `Number`        | число; `Int` является синонимом `Number`                           |
| `String`        | строка                                                             |
| `Boolean`       | булево значение `true` или `false`                                 |
| `Array<T>`      | массив с элементами типа `T`; просто `Array` означает `Array<Any>` |
| `Any`           | динамическое значение; статические проверки для него ослаблены     |
| `Unknown`       | значение неизвестного типа                                         |
| `Null`          | тип литерала `null`                                                |
| `T?`            | значение типа `T` или `null`                                       |
| `Void`          | отсутствие возвращаемого значения у функции                        |
| `(T1, T2) -> R` | функция с типами параметров `T1`, `T2` и результатом `R`           |

Функциональный тип планируемой функции с ошибками записывается как
`(T1, T2) -> R throws { E1, E2,... }`. `Void` допустим только как тип результата
функции, в том числе в функциональном типе: значения типа `Void` не существует,
поэтому его нельзя использовать для переменных, параметров и элементов массивов.

Примеры аннотаций:

```lynx
val count: Number = 10
var name: String = "Lynx"
val ready: Boolean = true
val items: Array<Number> = [1, 2, 3]    
val items: [Number] = [1, 2, 3]
val missing: Null = null
var nickname: String? = null
```

### Совместимость типов

- `Number`, `String`, `Boolean` и `Array` несовместимы друг с другом.
- Значение типа `Any` можно присвоить переменной любого типа; в `Any` также
  можно присвоить значение любого типа.
- `Unknown` можно присвоить только в `Unknown` или `Any`.
- `null` можно присвоить только в `Null`, nullable-тип, `Any` или `Unknown`.
- Nullable-значение нельзя присвоить в соответствующий non-nullable-тип без
  предварительного сужения.

`T?` описывает допустимое значение, а не необязательность аргумента. Например,
параметр `name: String?` всё равно обязателен при вызове, если у него нет
значения по умолчанию.

К `Unknown` и nullable-значениям нельзя напрямую применять арифметические
операторы, индексацию и `.length`. Проверка `value != null` сужает `T?` до `T`,
а `value is T` сужает `Unknown` до `T`:

```lynx
fun length(value: String?): Number {
  if value == null {
    return 0
  }
  return value.length
}

fun describe(value: Unknown): String {
  if value is String {
    return value
  }
  return "not a string"
}
```

Поддерживаются `is` и `!is`. В правой части `&&` действует сужение левого
условия, например `value != null && value.length > 0`. Для `||` аналогично
учитывается ложность левого условия. Проверка `Array<T>` во время выполнения
определяет только, что значение является массивом; тип элементов не проверяется.

### Массивы

Массивы создаются литералами:

```lynx
val numbers: Array<Number> = [1, 2, 3]
val first: Number? = numbers[0]
val size: Number = numbers.length
val empty: Array<Number> = []
```

Тип литерала выводится по элементам:

- `[1, 2, 3]` имеет тип `Array<Number>`;
- `[1, "two"]` — `Array<Any>`;
- `[1, null]` — `Array<Number?>`;
- `[]` без аннотации — `Array<Any>`.

Индекс должен иметь тип `Number` или `Any`. Индексация всегда возвращает
nullable-значение: при выходе за границы результатом является `null`. Поэтому
перед использованием элемента его нужно проверить:

```lynx
val row = matrix[0]
if row != null {
  val value = row[1]
}
```

Тот же принцип действует для строк: `word[0]` имеет тип `String?`.

## Выражения

Поддерживаются следующие операции, в порядке убывания приоритета:

1. вызов `f(x)`, индексация `a[i]`, доступ к свойству `a.length`;
2. унарные `+`, `-` и `!`;
3. умножение `*`, деление `/`, остаток `%`;
4. сложение `+` и вычитание `-`;
5. сравнения `<`, `<=`, `>`, `>=`, проверки `is` и `!is`;
6. равенство `==`, `!=`, `===`, `!==`;
7. логическое И `&&`;
8. логическое ИЛИ `||`.

Скобки изменяют порядок вычисления:

```lynx
val result = -(1 + 2) * 3
val ready = !false || 1 < 2 && 3 >= 3
```

Операторы `-`, `*`, `/`, `%` и упорядочивающие сравнения работают с числами.
Оператор `+` складывает числа или выполняет строковую конкатенацию:

```lynx
val message = "Result: " + 42
```

`&&` и `||` принимают `Boolean` и вычисляют правый операнд только при
необходимости. Оператор `!` выполняет логическое отрицание. Как и в других
операциях, `Any` разрешает динамическое поведение без полной статической
проверки.

Равенство всегда строгое, без неявного преобразования типов. Операторы `==` и
`===` эквивалентны, как и `!=` с `!==`:

- числа, строки и булевы значения сравниваются по значению;
- `null` равен только `null`;
- массивы и функции сравниваются по ссылке, а не по содержимому;
- несовместимые статические типы в сравнении вызывают ошибку компиляции;
- для `Any` и `Unknown` результат определяется во время выполнения по тем же
  правилам.

Индексация и `.length` доступны как для массивов, так и для строк:

```lynx
val word = "Lynx"
val firstCharacter: String? = word[0]
val length = word.length
```

Строки индексируются по кодовым единицам UTF-16, как в JavaScript. Результат
`word[i]` содержит одну кодовую единицу, которая не всегда соответствует целому
символу Unicode или графеме; `.length` возвращает количество кодовых единиц.

## Управляющие конструкции

### Условный оператор `if`

`if` выполняет блок, если условие истинно. Необязательный `else` задаёт
альтернативную ветвь, а цепочка `else if` проверяет несколько условий:

```lynx
if value > 0 {
  return "positive"
} else if value < 0 {
  return "negative"
} else {
  return "zero"
}
```

Как и в Go, скобки вокруг условия не требуются, а фигурные скобки обязательны.
Условие должно иметь тип `Boolean` (`Any` сохраняет динамическое поведение).
Выполняется только первая подходящая ветвь. Каждая ветвь создаёт собственную
область видимости.

### Циклы `for`

Цикл с условием повторяет тело, пока условие истинно:

```lynx
var i = 0
for i < 3 {
  i = i + 1
}
```

Трёхчастная форма содержит инициализацию, условие и пост-инструкцию:

```lynx
for var i = 0; i < 3; i = i + 1 {
  println(toString(i))
}
```

Переменная, объявленная в инициализации, видна только внутри цикла. Пост-
инструкцией может быть присваивание или вызов функции. Условие можно опустить:
`for { ... }` обозначает бесконечный цикл. `break` завершает ближайший цикл или
`switch`, а `continue` переходит к следующей итерации ближайшего цикла.

### Оператор `switch`

`switch` сравнивает значение выражения со значениями в `case` и выполняет первый
подходящий вариант:

```lynx
switch value {
case 0:
  return "zero"
case 1, 2:
  return "one or two"
default:
  return "other"
}
```

Семантика соответствует Go:

- выражение после `switch` вычисляется один раз;
- сравнение использует строгое равенство, описанное выше; типы `case` должны
  быть совместимы с типом выражения;
- один `case` может содержать несколько значений через запятую;
- выполняется только первый подходящий `case`; автоматического проваливания в
  следующий вариант нет, поэтому завершать каждый `case` через `break` не нужно;
- необязательный `default` выполняется, если не подошёл ни один `case`;
- `break` досрочно выходит из `switch`;
- `fallthrough` передаёт управление в следующий `case` без проверки условия и
  должен быть последней инструкцией не финального варианта;
- каждый `case` и `default` имеет собственную область видимости.

Выражение после `switch` можно опустить. Тогда варианты должны содержать булевы
условия и проверяются по порядку, как в `switch true`:

```lynx
switch {
case value < 0:
  return "negative"
case value > 0:
  return "positive"
default:
  return "zero"
}
```

## Функции

Общий синтаксис объявления:

```text
fun имя(параметр: Тип, параметр: Тип = значение): ТипВозврата {
  ...
  return выражение
}

fun имя(параметры): ТипВозврата throws { Ошибка1, Ошибка2 } {
  ...
}
```

Вторая форма относится к планируемой модели ошибок. Все параметры должны иметь
аннотацию типа. Тип возврата можно опустить — тогда функция имеет тип результата
`Void` и не возвращает значения.

```lynx
fun add(a: Number, b: Number = 1): Number {
  return a + b
}

fun log(value: Number) {
  return
}

val two = add(1)
val five = add(a = 2, b = 3)
```

### Параметры и аргументы

Значение по умолчанию задаётся через `=` и проверяется на совместимость с типом
параметра. Оно может ссылаться на ранее объявленные параметры:

```lynx
fun wrap(prefix: String, value: String = prefix): String {
  return value
}
```

Вызов поддерживает позиционные и именованные аргументы:

```lynx
add(1, 2)
add(1)
add(b = 5, a = 2)
```

Правила вызова:

- позиционный аргумент не может идти после именованного;
- один параметр нельзя передать дважды;
- все обязательные параметры должны получить аргумент;
- именованные аргументы переставляются в позиционные при генерации JavaScript,
  но выражения аргументов вычисляются слева направо в исходном порядке, поэтому
  перестановка не меняет порядок побочных эффектов;
- если между переданными аргументами пропущен параметр со значением по
  умолчанию, компилятор подставляет `undefined`.

Например:

```lynx
fun f(a: Number = 1, b: Number = 2): Number {
  return b
}

val result = f(b = 5) // JavaScript: f(undefined, 5)
```

Вариадический параметр записывается через `...` после типа:

```lynx
fun first(numbers: Number...): Number? {
  return numbers[0]
}

val value = first(1, 2, 3, 4)
```

Он должен быть последним и единственным вариадическим параметром функции, не
может иметь значения по умолчанию и не может быть передан по имени. Внутри
функции `numbers` имеет тип `Array<Number>`; в JavaScript используется
rest-параметр `...numbers`. Безопасная индексация объясняет тип результата
`Number?`.

### Возврат значения

- `return выражение` возвращает значение, совместимое с объявленным типом.
- Пустой `return` допустим только в функции с результатом `Void`, включая функцию
  без аннотации возврата.
- В функции с результатом `Void` инструкция `return выражение` запрещена.
- Если тип возврата отличен от `Void`, функция не может завершиться без значения
  или ошибки: каждый путь должен заканчиваться `return выражение`, `raise` либо
  ошибочным выходом через `?`. Бесконечный цикл без достижимого `break` также
  считается незавершающимся путём.

Компилятор учитывает `if`/`else`, `switch` с исчерпывающим `default` и
бесконечные циклы. Если возможно достичь конца такой функции без `return`,
`raise` или распространения ошибки, компиляция завершается ошибкой.

Сигнатуры функций собираются до проверки тел, поэтому доступны рекурсия, вызов
функций, объявленных ниже, и взаимные вызовы. Именованные функции можно
объявлять только на верхнем уровне программы.

## Лямбды и функциональные типы

Лямбда записывается в фигурных скобках: типизированные параметры, `->` и одно
выражение, результат которого возвращается:

```lynx
val sum = { x: Number, y: Number ->
  x + y
}

val total = sum(1, 5)
```

Результат транспиляции:

```js
const sum = (x, y) => x + y;
const total = sum(1, 5);
```

Тип лямбды выводится автоматически. Его также можно указать явно:

```lynx
val sum: (Number, Number) -> Number = {
  x: Number, y: Number -> x + y
}
```

Функциональные типы допустимы в параметрах и возвращаемых значениях:

```lynx
fun apply(f: (Number) -> Number, value: Number): Number {
  return f(value)
}

val incremented = apply({ n: Number -> n + 1 }, 10)
```

Лямбда без параметров записывается как `{ -> 42 }`. Лямбды поддерживают
замыкания:

```lynx
val outer = { x: Number -> { y: Number -> x + y } }
val addOne = outer(1)
val result = addOne(41) // 42
```

Текущие ограничения:

- тело лямбды состоит из одного выражения; блок и `return` недоступны;
- все параметры должны иметь типы;
- значения по умолчанию и вариадические параметры не поддерживаются;
- тело должно производить значение, поэтому вызов функции с результатом `Void`
  не может быть выражением-результатом лямбды;
- именованные аргументы при вызове функции-значения не поддерживаются;
- вызывать можно только имя функции или переменной: вызов произвольного
  выражения, например `functions[0](1)`, пока недоступен.

## Стандартная библиотека

Минимальная стандартная библиотека доступна без импорта:

| Функция                        | Результат | Назначение                                   |
|--------------------------------|-----------|----------------------------------------------|
| `println(value: Any)`          | `Void`    | вывести значение в stdout с переводом строки |
| `toString(value: Any): String` | `String`  | преобразовать значение в строку              |

```lynx
val answer = 42
println("Answer: " + toString(answer))
```

В JavaScript `println` преобразуется в `console.log`, а `toString` — в `String`.
Встроенные функции нельзя переобъявить.

## Enum (перечисления)

> `enum` и `match` описаны как планируемые возможности, поведение которых
> следует модели Rust. Текущая версия компилятора их не поддерживает.

Enum определяет один тип с несколькими именованными вариантами. В отличие от
простого перечисления констант, вариант может содержать дополнительные данные:

```lynx
enum Message {
  Quit,
  Move { x: Number, y: Number },
  Write(String),
  ChangeColor(Number, Number, Number),
}
```

Поддерживаются три формы вариантов Rust:

- **единичный** — `Quit`, не содержит данных;
- **структурный** — `Move { x: Number, y: Number }`, содержит именованные поля;
- **кортежный** — `Write(String)`, содержит позиционные значения.

Все варианты `Message` имеют тип `Message`, а не отдельные несовместимые типы.
Обращение к варианту выполняется через имя enum:

```lynx
val quit = Message.Quit
val move = Message.Move(x = 10, y = 20)
val write = Message.Write("Hello")
val color = Message.ChangeColor(255, 128, 0)
```

Enum может иметь параметры типа:

```lynx
enum Either<L, R> {
  Left(L),
  Right(R),
}
```

### Сопоставление с образцом `match`

`match` безопасно разбирает enum по вариантам и связывает содержащиеся в них
значения с переменными:

```lynx
fun render(message: Message): String {
  return match message {
    Message.Quit -> "quit",
    Message.Move { x, y } -> "move to " + toString(x) + ", " + toString(y),
    Message.Write(text) -> text,
    Message.ChangeColor(r, g, b) -> "color",
  }
}
```

Правила соответствуют Rust:

- `match` является выражением и возвращает результат выбранной ветви;
- все ветви должны возвращать значения совместимых типов;
- перечисление вариантов должно быть **исчерпывающим** — компилятор отклоняет
  `match`, если возможен необработанный вариант;
- `_` обозначает универсальный образец и обрабатывает все оставшиеся варианты;
- поля структурного варианта можно записывать сокращённо: `{ x, y }` вместо
  `{ x = x, y = y }`;
- переменные образца доступны только внутри соответствующей ветви;
- ветви не проваливаются друг в друга и не требуют `break`.

Пример с универсальным образцом:

```lynx
val description = match message {
  Message.Write(text) -> text,
  _ -> "other message",
}
```

## Возврат ошибок из функций

> `throws`, `raise`, `try`/`catch`, `.context(...)` и оператор распространения
> ошибки `?` являются планируемыми возможностями. Текущая версия компилятора их
> не поддерживает.

Функция перечисляет возможные типы ошибок в `throws`. Обычный результат и ошибки
передаются по разным каналам: после двоеточия указывается тип успешного
результата, а в фигурных скобках после `throws` — все допустимые ошибки.

```lynx
fun load(path: String): Config throws { IoError, ParseError, ConfigError } {
  // ...
}
```

В отличие от непроверяемых исключений, набор ошибок является частью типа
функции. Компилятор не позволяет поднять или молча распространить ошибку,
которая не перечислена в `throws`. В функциональном типе набор записывается после
типа результата:

```lynx
val loader: (String) -> Config throws { IoError, ParseError, ConfigError } = load
```

Лямбда, распространяющая ошибку через `?`, имеет функциональный тип с
соответствующим `throws`. Например, типом
`{ text: String -> parseInt(text)? }` является
`(String) -> Number throws { ParseError }`.

### Полный пример

В `throws` можно перечислять только типы enum, включая enum с данными в
вариантах. Классы, `Any`, `Unknown`, nullable-типы и произвольные значения не
могут выступать типами ошибок:

```lynx
enum IoError {
  NotFound,
  PermissionDenied,
}

enum ParseError {
  InvalidNumber(String),
}

enum ConfigError {
  InvalidPort(Number),
}

class Config(val port: Number, val workers: Number)

fun load(path: String): Config throws { IoError, ParseError, ConfigError } {
  val text = readFile(path).context("reading config")?
  val port = parseInt(findField(text, "port")).context("parsing port")?

  if port < 1 || port > 65535 {
    raise ConfigError.InvalidPort(port)
  }

  val workers = parseInt(findField(text, "workers"))?
  return Config(port = port, workers = workers)
}
```

Здесь предполагается, что `readFile` объявляет `throws { IoError }`, а
`parseInt` — `throws { ParseError }`. Функция `load` может вернуть `Config`
либо завершиться одной из трёх явно объявленных ошибок.

### `raise`

`raise` завершает выполнение функции и возвращает указанную ошибку вызывающей
стороне:

```lynx
raise ConfigError.InvalidPort(port)
```

Тип значения после `raise` должен входить в список `throws`. Само значение может
быть единичным, кортежным или структурным вариантом enum, поэтому ошибка сохраняет
свой тип и связанные с ней данные.

### Оператор `?`

Постфиксный `?` распространяет ошибку вызываемой функции:

```lynx
val text = readFile(path)?
```

- при успехе выражение возвращает обычное значение, например `String`;
- при ошибке текущая функция досрочно завершается с той же ошибкой;
- каждый распространяемый тип должен входить в `throws` текущей функции;
- неявных преобразований между типами ошибок нет;
- `?` относится к ошибкам и не заменяет проверки nullable-типов: запись
  `String?` по-прежнему обозначает значение или `null`.

Если вызываемая функция объявляет несколько ошибок, все они должны быть
допустимы в текущей функции либо обработаны через `try`/`catch`.

### Контекст ошибки

Метод `.context(message)` добавляет человекочитаемое описание к возможной
ошибке, сохраняя её исходный тип:

```lynx
val text = readFile(path).context("reading config")?
val port = parseInt(input).context("parsing port")?
```

При ошибке `readFile` наружу распространяется исходная `IoError`, дополненная
контекстом `reading config`. Несколько вложенных вызовов `.context(...)` образуют
цепочку контекстов; вариант ошибки и её данные при этом не меняются.

### Обработка через `try`/`catch`

Функция без подходящего `throws` обязана обработать ошибку явно:

```lynx
try {
  val config = load("config.lynx")
  println("port: " + toString(config.port))
} catch (error: IoError) {
  println("I/O error")
} catch (error: ParseError) {
  println("parse error")
} catch (error: ConfigError.InvalidPort(port)) {
  println("invalid port: " + toString(port))
}
```

`catch` выбирается по типу и, при необходимости, по варианту ошибки. Типы из
`throws` должны быть покрыты обработчиками либо перечислены в `throws` текущей
функции. Для сложного разбора одной ошибки внутри `catch` можно использовать
исчерпывающий `match`.

## ООП

> `class` и `interface` описаны как планируемые возможности. Их поведение должно
> соответствовать Kotlin, но текущая версия компилятора их ещё не поддерживает.

### Классы

Класс объявляется через `class`. Конструктор записывается в заголовке
класса; его параметры, помеченные `val` или `var`, становятся свойствами:

```lynx
class User(val name: String, var age: Number = 0) {
  fun greet(): String {
    return "Hello, " + name + "!"
  }
}

val user = User("Lynx", 3)
val renamed = User(name = "world")
```

Результат транспиляции:

```js
class User {
    constructor(name, age = 0) {
        this.name = name;
        this.age = age;
    }

    greet() {
        return "Hello, " + this.name + "!";
    }
}

const user = new User("Lynx", 3);
```

Свойство объявляется через `val` (только чтение) или `var` (изменяемое). Его
можно описать и в теле класса:

```lynx
class Counter(val start: Number = 0) {
  var count: Number = start

  fun increment(): Number {
    count = count + 1
    return count
  }
}

val counter = Counter()
val next = counter.increment()
```

Объект создаётся вызовом `ИмяКласса(аргументы)`, без `new`. Значения по
умолчанию, позиционные и именованные аргументы работают так же, как у функций.
Доступ к членам — через точку:

```lynx
val user = User("Lynx")
val greeting = user.greet()
user.age = 4
```

#### Наследование

Родительский класс указывается после двоеточия вместе с аргументами
своего конструктора:

```lynx
class Animal(val name: String) {
  fun speak(): String {
    return "..."
  }
}

class Dog(val name: String): Animal(name) {
  override fun speak(): String {
    return "Woof"
  }
}

class QuietDog(val name: String): Dog(name) {
  override fun speak(): String {
    return "[" + super.speak() + "]"
  }
}
```

Переопределение
помечается `override`; реализация родителя доступна через `super`.

#### Абстрактные классы

Абстрактный класс объявляется через `abstract class` и не может быть создан
напрямую. Абстрактный метод не имеет тела и обязан быть переопределён:

```lynx
abstract class Shape {
  abstract fun area(): Number

  fun describe(): String {
    return "area = " + area()
  }
}

class Square(val side: Number): Shape {
  override fun area(): Number {
    return side * side
  }
}
```

Правила:

- классы объявляются на верхнем уровне программы, как именованные функции;
- класс наследует не более одного класса; интерфейсы перечисляются после
  родителя через запятую;
- члены класса публичны; модификаторы доступа (`private`, `protected`,
  `public`) появятся позже;

### Интерфейсы

Интерфейс задаёт контракт без состояния. Метод без тела — абстрактный; метод с
телом даёт реализацию по умолчанию. Свойства объявляются без начального
значения:

```lynx
interface Named {
  val name: String

  fun describe(): String {
    return "named " + name
  }
}

interface Serializable {
  fun serialize(): String
}

class User(val name: String, val age: Number): Named, Serializable {
  override fun serialize(): String {
    return name + " (" + age + ")"
  }
}

val user = User("Lynx", 3)
val description = user.describe() // "named Lynx" — реализация по умолчанию
```

Правила:

- методы с телом можно не переопределять; методы без тела класс обязан
  реализовать, переопределение помечается `override`;
- свойства интерфейса не хранят значения — их предоставляет класс;
- если два интерфейса дают реализацию одного и того же метода, класс должен
  переопределить его сам;
- интерфейсы существуют только во время компиляции: в JavaScript они не
  попадают, а реализация по умолчанию подставляется в классы, которые её не
  переопределили.

## Диагностика ошибок

Компилятор сообщает имя файла, строку, столбец и показывает фрагмент исходника:

```text
$ ./bin/lynxc bad.lynx
bad.lynx:1:17: error: cannot assign a value of type String to variable "a" of type Number
val a: Number = "x";
                ^
```

Одна компиляция может вывести несколько независимых ошибок проверки типов.
JavaScript не генерируется, если программа содержит ошибки.
